Verify a sealed disclosure

W/P DECC-26browser verifier 0.1.0, DECC-26 rev.1

Drop in a disclosure bundle. The page checks that every disclosed record reopens its commitment and that the disclosed set came from a sealed population of the committed size, so a partial disclosure cannot hide how much was held back. Nothing is uploaded and no network request is made.

How to read this

A verdict of VERIFIED means each disclosed record's content hash and commitment reopen from the salt and metadata given, and each record's inclusion proof leads to the anchored root under the anchored count. A supplied anchor must match the anchor embedded in the bundle; that comparison is what binds the disclosure to a record the operator does not control.

The percentage disclosed is the count in the bundle over the count in the anchor. An inclusion proof alone does not fix the count; the anchor's sha256 does. Compare it with the published record before relying on the percentage.

You do not have to trust the party who gave you the bundle, and you do not have to trust this page: read the source, it is all here.

Re-performance

Every verdict this page gives can be reproduced without it.

  1. Read the source of this page; the verification code is the whole of its script and calls nothing outside your browser.
  2. Re-run the same bundle with the reference implementation from a clone of the repository: python denom.py verify-bundle bundle.json --anchor anchor.json.
  3. Check either implementation against the standard's known-answer vectors: python decc_conformance.py reads DECC_TEST_VECTORS.json, thirty-eight vectors stated in full.
  4. Compare the anchor sha256 below with the operator's published anchor record; if they differ, the count on this page is not the count that was published.
